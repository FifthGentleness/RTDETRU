## RT-DETR Decoder 全景细分改进方向

### 一、Query 数量与初始化（query 从哪来）

| # | 方向 | 具体做法 | 相关度 |
| --- | --- | --- | --- |
| 1.1 | **Query 数量扩容** | `nq` 300→600/900（yaml 直接改） | ★★★ 漏检主因 |
| 1.2 | **密度感知分配** | 特征图分网格，每格保底名额，防止 query 被密集车流吸走 | ★★★ 论文级创新 |
| 1.3 | **学习式初始 query** | `learnt_init_query=True`（你代码里已有开关），anchor-free 学习嵌入与 encoder 选择混合 | ★★ |
| 1.4 | **混合 query 源** | 一半 encoder top-K 选择 + 一半内容无关的可学习 query（H-DETR 思路），补盲区 | ★★ |
| 1.5 | **锚点初始化** | 用数据集统计的先验框/密度热图生成初始 reference points，而非均匀 grid | ★★ |

### 二、Query Selection（encoder→decoder 的选拔机制）

| # | 方向 | 具体做法 | 相关度 |
| --- | --- | --- | --- |
| 2.1 | **质量感知 top-K** | 选择分数 = 分类分数 × IoU-aware 定位质量，淘汰“高分低框” | ★★★ |
| 2.2 | **空间配额选择** | top-K 前先做网格去重，保证空间覆盖（治“小目标饿死”） | ★★★ |
| 2.3 | **级联两轮选择** | 粗选 2K → 轻量打分器精选 K，选择器本身可学习 | ★★ |
| 2.4 | **选择分数温度/分布** | focal-style 加权让低置信小目标也有入选概率 | ★ |
| 2.5 | **多尺度均衡选择** | 每个 FPN 层级各自 top-K 配额，防 P5 大目标垄断 | ★★ |

### 三、去噪训练（CDN，训练专属，零推理成本）

| # | 方向 | 具体做法 | 相关度 |
| --- | --- | --- | --- |
| 3.1 | **去噪组数 `nd`** | 100→300（配合 nq=600 同步放大） | ★★★ |
| 3.2 | **box 噪声尺度** | `box_noise_scale` 1.0→1.5~2.0，小目标定位鲁棒性 | ★★ |
| 3.3 | **label 噪声比例** | `label_noise_ratio` 0.5 微调，治你的 cls 过拟合 | ★★ |
| 3.4 | **动态噪声调度** | 训练前期大噪声后期小噪声（curriculum denoising） | ★ |
| 3.5 | **多组正负去噪** | DN-DETR 式多组互不匹配的噪声组，增强匹配稳定性 | ★ |

### 四、Self-Attention 结构（query 之间的交互）

| # | 方向 | 具体做法 | 相关度 |
| --- | --- | --- | --- |
| 4.1 | **稀疏 query 注意力** | 你已实现的 NSQ：按 IoU 找竞争对去重 + 压缩 + 窗口三分支 | ★★★ 已就绪 |
| 4.2 | **Gram 约束（QGA）** | 训练期惩罚重叠 query 特征相似度，零推理成本 | ★★★ 已就绪 |
| 4.3 | **局部分窗注意力** | query 按空间位置分窗，窗口内交互，降 nq² 成本 | ★ |
| 4.4 | **逐层稀疏度递增** | 浅层全交互保留多样性、深层稀疏化做去重 | ★ |

### 五、Cross-Attention（query ↔ 特征交互）

| # | 方向 | 具体做法 | 相关度 |
| --- | --- | --- | --- |
| 5.1 | **采样点数 `ndp`** | 4→8（你 yaml 里第 4 个参数），小目标需要更密采样 | ★★★ |
| 5.2 | **交互层级** | 现在只吃 f3/f4/f5 三层；P2 特征（你的 CCFFP2V7 里 128ch 分支）是否也喂给 decoder 可评估 | ★ |
| 5.3 | **可变形注意力增强** | DCNv3/DCNv4 算子替换（你 extra_modules 里有现成 op） | ★ |
| 5.4 | **隐维度 `hd`** | 256→192 可省算力 / 320 提容量（先不动，收益不稳） | ★ |

### 六、Decoder 深度与监督

| # | 方向 | 具体做法 | 相关度 |
| --- | --- | --- | --- |
| 6.1 | **层数 `ndl`** | 3→4（r50 用 6，r18 的 3 偏少） | ★★★ |
| 6.2 | **层间权重共享** | 层数加深后共享部分层参数，控制参数量 | ★ |
| 6.3 | **迭代框精调** | 确认 look-forward-twice 逐层 box 精调已启用（RT-DETR 默认有） | 检查项 |
| 6.4 | **辅助监督** | 每层 aux loss 已有；可加浅层的深度监督权重衰减调度 | ★ |
| 6.5 | **eval_idx** | 用倒数第 2 层输出而非最后一层（有时浅层 P-R 更均衡） | ★ 免费实验 |

### 七、分类/回归头与匹配（decoder 侧 Loss）

| # | 方向 | 具体做法 | 相关度 |
| --- | --- | --- | --- |
| 7.1 | **IoU-aware 分类头** | 分类分支额外预测定位质量，推理时分数融合（治 P-R 失衡） | ★★★ |
| 7.2 | **匹配代价重调** | Hungarian matcher 的 cls/focal 代价比例，向召回倾斜 | ★★ |
| 7.3 | **VFL/质量 focal loss** | 替换 BCE，让正样本分数对齐 IoU | ★★ |
| 7.4 | **一对多辅助匹配** | H-DETR 式每 GT 配多 query 的 aux 分支，训练期增密监督，推理删除 | ★★ R 收益明显 |
| 7.5 | **类别不均衡处理** | bicycle/awning-tricycle 样本少，matching 代价或 loss 按类别频率加权 | ★★ 针对你最差两类 |

### 八、推理与部署侧

| # | 方向 | 具体做法 | 相关度 |
| --- | --- | --- | --- |
| 8.1 | **max_det 同步** | val/predict `max_det` 300→600（不改这个前面全白做） | ★★★ 前置条件 |
| 8.2 | **置信度阈值策略** | 评估时 conf 阈值降低，释放低分小目标（会掉 P，先看清上限） | ★ 诊断用 |
| 8.3 | **top-K 输出重排** | 输出前按“分类×质量”重排而非纯分类分数 | ★ |

## 优先组合建议（结合你的实际数据）

```
前置（零代码）：  8.1 max_det + 1.1 nq + 3.1 nd        ← 掀 Recall 天花板
高性价比（改参）：6.1 ndl + 5.1 ndp + 3.2/3.3 噪声微调
创新点候选：     2.2 空间配额选择（数据支撑最强）
                4.1 NSQ + 4.2 QGA（已实现，先跑通）
                7.1 IoU-aware 头 + 7.4 一对多辅助匹配
```

细分方向里，**一、二、三、八**四个子系统全部指向你的核心病灶（漏检），**七**指向 P-R 失衡和最差类别，**四**是你已经投入过的方向（NSQ/QGA），**五、六**是常规容量扩展。建议严格按照前置→改参→创新的顺序做，每个变量单独验证。
